# Git Tips and Procedures

## Rewriting Multiple Commit Messages

When you need to remove or modify text from multiple commit messages (e.g., removing stamps, fixing typos), use `git filter-branch`:

### Steps

1. **Stash any uncommitted changes first:**
   ```bash
   git stash
   ```

2. **Find the commits that need rewriting:**
   ```bash
   git log --grep="text to find" --oneline
   ```

3. **Identify the parent commit of the oldest commit to rewrite:**
   ```bash
   git log --oneline -20
   ```

4. **Run filter-branch with sed to modify messages:**
   ```bash
   FILTER_BRANCH_SQUELCH_WARNING=1 git filter-branch -f --msg-filter 'sed "/pattern to remove/d"' <parent-commit>^..HEAD
   ```

   Example - removing multiple patterns:
   ```bash
   FILTER_BRANCH_SQUELCH_WARNING=1 git filter-branch -f --msg-filter 'sed "/line to delete 1/d; /line to delete 2/d"' abc1234^..HEAD
   ```

5. **Verify the changes:**
   ```bash
   git log --grep="removed text" --oneline  # Should return fewer/no results
   git log -3 --format="%h%n%B---"           # Check recent commit messages
   ```

6. **Restore stashed changes:**
   ```bash
   git stash pop
   ```

### Important Notes

- `^` after the commit hash means "parent of this commit"
- The `FILTER_BRANCH_SQUELCH_WARNING=1` suppresses the warning about filter-branch
- This rewrites commit history - only use on commits that haven't been pushed, or coordinate with team if they have
- The `-f` flag forces the rewrite even if a backup exists from a previous filter-branch

### Alternative: Interactive Rebase (for fewer commits)

For rewriting just a few commits, interactive rebase may be simpler:

```bash
git rebase -i <parent-commit>
# Mark commits as "reword" (r) in the editor
# Save and edit each commit message when prompted
```

## Commit Message Guidelines

- Do NOT add any stamps, signatures, or "Generated by" text to commit messages
- Keep messages concise but descriptive
- Use conventional commit format: `type: description`
  - `feat:` - new feature
  - `fix:` - bug fix
  - `docs:` - documentation
  - `test:` - tests
  - `style:` - formatting
  - `refactor:` - code restructuring
  - `chore:` - maintenance
